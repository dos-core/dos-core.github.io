Kernels

FreeDOS Kernel

The kernel of the FreeDOS project. It grew out of Pat Villani's DOS-C and has been maintained by the FreeDOS community since the 1990s. Ships as a single KERNEL.SYS. FAT12 and FAT16 are supported. FAT32 support and minimum CPU requirements depend on the build.

Upstream
github.com/FDOS/kernel
Project
freedos.org
Mirror
github.com/dos-core/fdkernel
License
GNU GPL v2 or later

Enhanced DR-DOS (SvarDOS)

The DR-DOS line, descended from the Caldera OpenDOS 7.01 sources, moved over to JWasm and OpenWatcom. It is the default kernel in SvarDOS. Builds either the classic DRBIO.SYS + DRDOS.SYS pair or a single KERNEL.SYS that follows the FreeDOS load protocol.

SvarCOM

Mateusz Viste's command interpreter for SvarDOS. Small, written in C, and keeps only a tiny resident part in memory. The mirror carries the whole SvarDOS core tree; the shell is in svarcom/.

4DOS

Rex Conn's replacement shell from JP Software, the one with aliases, command-line editing, DESCRIPT.ION and the batch language everyone wished COMMAND.COM had. JP Software released the 7.50 source in 2004, and Luchezar Georgiev carried it forward through 8.00.

4DOS never had a public version control history, so this one is rebuilt from the published source releases and patch archives. Tags without a suffix match a published source release. Tags ending in -est are estimates pieced together from changelogs and later patches; treat them as a best guess at history, not a released version. This is recommended for most compatible in running programs but pay attention to its license prior to use.

Build support

ecm companion repositories

lDOS, ecm's EDR-DOS and RxDOS expect a handful of ecm's other repositories sitting next to them: macros, boot loaders, the compressor, the sector installer and so on. Each one is mirrored into its own subdirectory of a single Git repository, with the converted Git history included through subtree merges.

Using it
Point the build at the subdirectory, for example LMACROS_DIR=../ecm/lmacros/

How the mirrors are kept

  • Git sources are fetched and the main branch is fast-forwarded when possible.
  • Mercurial sources are pulled and converted with hg-git. The default branch becomes main; named branches become hg/<name>.
  • The ecm repository adds integration commits for its subtrees. The 4DOS history is reconstructed from source archives.
